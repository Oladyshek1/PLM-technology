## Общие правила

### Формат данных
- Запросы и ответы: **JSON**, UTF-8
- Content-Type: `application/json`

### Базовый URL
http://127.0.0.1:8000

Префикса `/api/v1` нет. Swagger: `http://127.0.0.1:8000/docs`

### Модель времени
Бронь — **один готовый период** из справочника `GET /times` (обычно 1 час: 08:00–09:00 … 21:00–22:00).

| Что | Формат | Пример |
|-----|--------|--------|
| Дата | `YYYY-MM-DD` | `2026-10-15` |
| Время периода | `HH:MM:SS` | `10:00:00` |
| Выбор слота | целое `time_id` | `3` |

Произвольный интервал `start_time`/`end_time` в запросе **не принимается**.

### Статусы брони
| Статус | Значение |
|--------|----------|
| `ACTIVE` | Активная бронь (учитывается в накладках) |
| `CANCELLED` | Отменена (в накладках **не** учитывается) |

Статусы `PENDING` / `CONFIRMED` в текущей реализации **не используются**.

### Накладки
- Пересечение периодов на одном ресурсе в одну дату → `409`
- Стык (10:00–11:00 и 11:00–12:00) — **не** накладка
- Проверка атомарна: `SELECT … FOR UPDATE` в транзакции

### Ошибки
FastAPI: тело вида `{"detail": "текст или структура"}`  
(не `{"error","message"}`).

| Код | Когда |
|-----|--------|
| 200 | Успех чтения / отмены |
| 201 | Создан пользователь или бронь |
| 400 | Неверный запрос (прошедшее время, плохой диапазон дат и т.п.) |
| 404 | Не найден ресурс / пользователь / период / бронь |
| 409 | Накладка или телефон уже зарегистрирован |
| 422 | Ошибка валидации тела/параметров |

## Модели

### Resource
```json
{
  "id": 1,
  "name": "Переговорная А",
  "area": 20,
  "capacity": 8,
  "equipment": "проектор",
  "working_hours": {
    "start": "08:00:00",
    "end": "22:00:00",
    "period_minutes": 60
  }
}
Time period (из GET /times)
{
  "id": 3,
  "start_time": "10:00:00",
  "end_time": "11:00:00"
}
(точные ключи — как отдаёт get_periods() / Swagger; ориентир: id + начало/конец)

User
{
  "id": 1,
  "name": "Иван Иванов",
  "phone": "+79001234567"
}
Booking (элемент GET /bookings)
{
  "id": 42,
  "user_id": 1,
  "user": "Иван Иванов",
  "resource": "Переговорная А",
  "status": "ACTIVE",
  "time_id": 3,
  "start_time": "10:00:00",
  "end_time": "11:00:00",
  "date": "2026-10-15"
}
Поля resource_id в списке сейчас нет (только название resource) — для переноса фронту нужно либо искать ресурс по имени, либо доработать бэкенд.

Endpoints
GET /settings
Настройки сетки.

200

{
  "working_hours": {
    "start": "08:00:00",
    "end": "22:00:00",
    "period_minutes": 60
  },
  "periods_count": 14,
  "now": "2026-10-25T19:00:00"
}
GET /times
Справочник периодов бронирования (массив объектов периода).

GET /resources
Список помещений — голый массив (без обёртки {"resources": ...}).

GET /users
Список пользователей. Query (необязательно):

phone — точное совпадение
name — точное совпадение
«Вход» на фронте = поиск по phone + name. Авторизации / токенов нет.

POST /users → 201
Регистрация.

Тело

{
  "name": "Иван Иванов",
  "phone": "+79001234567"
}
201

{
  "id": 3,
  "name": "Иван Иванов",
  "phone": "+79001234567"
}
409 — телефон уже есть: {"detail":"аккаунт с таким телефоном уже есть"}

GET /bookings
Список броней — голый массив.

Query (все необязательны):

Параметр	Тип	Назначение
user_id	int	«Мои брони»
booking_date	date	Один день
date_from	date	Начало диапазона
date_to	date	Конец диапазона
resource_id	int	Одно помещение
400 если date_from > date_to.

POST /bookings → 201
Создать бронь (атомарно).

Тело

{
  "user_id": 1,
  "resource_id": 2,
  "booking_date": "2026-10-15",
  "time_id": 3
}
201

{
  "id": 42,
  "user_id": 1,
  "resource_id": 2,
  "date": "2026-10-15",
  "time_id": 3,
  "start_time": "10:00:00",
  "end_time": "11:00:00",
  "status": "ACTIVE"
}
Код	detail (смысл)
400	нельзя бронировать прошедшее время
404	период / ресурс / пользователь не найден
409	накладка: это время уже занято
422	невалидное тело
POST /bookings/{id}/cancel → 200
Отменить бронь (статус → CANCELLED).

200

{
  "id": 42,
  "status": "CANCELLED"
}
404 — бронь не найдена.

Известные ограничения (см. Issues #13): проверка владельца не делается; повторная отмена сейчас тоже 200 (желаемое поведение — 400 already_cancelled).
