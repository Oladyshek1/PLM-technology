# Система бронирования помещений «ТаймРум» (PLM-technology)

Веб-система для бронирования общих помещений (переговорных и залов). Пользователь регистрируется, выбирает помещение и свободный слот в сетке рабочего дня, создаёт бронь, смотрит свои записи, переносит или отменяет их. Администратор видит все брони, сводку занятости и может отменить чужую бронь.

Интерфейс в браузере: пользовательский — `docs/frontend/index.html`, административный — `docs/frontend/admin.html`. API — FastAPI на `http://127.0.0.1:8000`. Данные — встроенный PostgreSQL (пакет `pgserver`), база `booking`.

Исходники: [git.mf.csu.ru/rodsd_mfi401/PLM-technology](https://git.mf.csu.ru/rodsd_mfi401/PLM-technology).

## Возможности

**Пользователь**

- Регистрация и вход (имя и телефон; сессия хранится в браузере).
- Главная: карусель помещений и их характеристики из API.
- Бронирование: недельный календарь, скрытие занятых и прошедших слотов, выбор одного или нескольких слотов подряд, атомарное создание (все слоты или ни одного).
- «Мои брони»: фильтры по помещению и датам; закончившиеся брони (конец слота ≤ текущее время сервера) и отменённые скрываются.
- Отмена своей брони и перенос (на клиенте: создать новую → отменить старую; если отмена не удалась, новая тоже отменяется).
- Окно «i»: название, версия, дата сборки и контакты поддержки из `GET /version`.

**Администратор**

- Отдельная страница `admin.html` с входом по имени и паролю (токен сессии на 12 часов).
- Таблица всех броней (включая прошедшие и отменённые), фильтры по помещению и датам, поиск по имени заказчика, сортировка по времени, дата создания брони.
- Сводка занятых часов по помещениям за период (`GET /summary`).
- Отмена любой брони, кроме уже начавшейся или прошедшей.

Учётные данные администратора выдаёт тимлид. В документации они не публикуются.

## Быстрый старт (Windows)

Рабочая папка бэкенда — `docs\bd`. Именно там появляются `pgdata` и оттуда запускается `uvicorn`.

```bat
cd docs\bd
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install fastapi "uvicorn[standard]" pgserver psycopg2-binary bcrypt
python init_db.py
uvicorn app:app --reload
```

- API и Swagger: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) (`GET /` перенаправляет на `/docs`).
- Пользовательский интерфейс: откройте в браузере файл `docs\frontend\index.html`.
- Интерфейс администратора: файл `docs\frontend\admin.html`.
- Фронт обращается к `http://127.0.0.1:8000` (константа в HTML). Сначала должен быть запущен API.

`init_db.py` идемпотентен: повторный запуск безопасен и не дублирует справочники. Пароль администратора берётся из переменной окружения `ADMIN_PASSWORD`; если её нет, скрипт генерирует пароль и **один раз печатает его в консоль** — сохраните его. Учётные данные администратора в любом случае выдаёт тимлид.

### Если база не поднимается

После остановки `uvicorn` процесс PostgreSQL иногда остаётся в памяти, а папка `pgdata` оказывается занята. Типичные симптомы: таймаут `init_db.py` или ошибка доступа к файлам в `pgdata`.

1. Остановить сервер API (окно с `uvicorn`).
2. Завершить оставшийся Postgres:

   ```bat
   taskkill /F /IM postgres.exe
   ```

   Если процесс уже не найден, сообщение «Не удается найти процесс postgres.exe» можно игнорировать.

3. Удалить локальные данные БД **из папки `docs\bd`**:

   ```bat
   cd docs\bd
   rmdir /S /Q pgdata
   ```

   Команда — `rmdir`, не `trmdir`. Будут удалены только локальные данные в `pgdata`; в git их нет.

4. Снова выполнить `python init_db.py`, затем `uvicorn app:app --reload`.

Не используйте Python 3.13 для этого проекта: `pgserver` на нём не ставится.

## Кратко об API

Базовый URL: `http://127.0.0.1:8000` (без префикса `/api/v1`). Ошибки: `{"detail": "..."}`. Подробности и примеры — в Wiki [[API]](https://git.mf.csu.ru/rodsd_mfi401/PLM-technology/wiki/API) и в [`docs/API_CONTRACT.md`](docs/API_CONTRACT.md).

| Метод | Путь | Кто может вызывать | Назначение |
|-------|------|--------------------|------------|
| GET | `/` | все | Редирект на `/docs` |
| GET | `/version`, `/api/version` | все | Версия продукта, дата сборки, контакты поддержки |
| GET | `/settings` | все | Рабочие часы, шаг слота, число периодов, текущее время сервера |
| GET | `/times` | все | Справочник периодов сетки (сеансы) |
| GET | `/availability` | все | Свободные и ещё не начавшиеся периоды помещения на дату |
| GET | `/resources` | все | Список помещений |
| GET | `/users` | все | Список пользователей; фильтры `phone`, `name` (точное совпадение) |
| POST | `/users` | все | Регистрация (роль всегда `USER`) |
| POST | `/auth/admin-login` | администратор | Вход, выдача токена на 12 часов |
| POST | `/auth/admin-logout` | администратор | Отзыв токена |
| GET | `/bookings` | пользователь: свой `user_id`; администратор: `token` | Список броней, фильтры и сортировка |
| GET | `/summary` | только администратор (`token`) | Сводка часов занятости по помещениям за период |
| POST | `/bookings` | все (нужен существующий `user_id`) | Создать бронь(и) со статусом `PENDING` |
| POST | `/bookings/{id}/confirm` | владелец брони (`user_id`) | `PENDING` → `CONFIRMED` |
| POST | `/bookings/{id}/cancel` | владелец или администратор | → `CANCELLED` |

## Роли и статусы

| Роль | Как появляется | Права в API |
|------|----------------|-------------|
| `USER` | Регистрация `POST /users` | Свои брони, отмена только своих; без `token` нельзя смотреть все брони, искать по заказчику и вызывать `/summary` |
| `ADMIN` | Только `init_db.py`, не через регистрацию | Все брони, поиск, сводка, отмена чужой брони (кроме уже начавшейся) |

| Статус брони | Смысл | Слот |
|--------------|--------|------|
| `PENDING` | Создана, ожидает подтверждения | занят |
| `CONFIRMED` | Подтверждена | занят |
| `CANCELLED` | Отменена | свободен |

Жизненный цикл: создание → `PENDING` → подтверждение владельцем → `CONFIRMED`. Из `PENDING` или `CONFIRMED` можно отменить → `CANCELLED`. Старый статус `ACTIVE` не используется (`init_db.py` переводит такие строки в `CONFIRMED`).

Сетку времени задаёт таблица «Время»: по умолчанию 08:00–22:00 с шагом 60 минут (14 периодов). Прошедшую или уже начавшуюся бронь нельзя подтвердить, отменить или перенести (сервер отвечает 409).

## Правила валидации при регистрации

Одинаковые правила проверяют API (ответ 422) и ограничения PostgreSQL.

- **Имя:** только буквы (кириллица и латиница), пробел и дефис; от 2 до 100 символов; должно начинаться с буквы. В базе дополнительно запрещены цифры и проверяется длина 2–100.
- **Телефон:** нормализуется к виду `+7` и ровно 10 цифр (`+7XXXXXXXXXX`). Входные `8XXXXXXXXXX` и номер с пробелами, скобками и дефисами тоже приводятся к этому виду. Номер уникален.
